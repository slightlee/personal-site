# PRD: personal-site

## 1. 背景

`personal-site` 是一个个人网站，用于展示个人信息、能力标签、作品集、文章或项目案例，并作为对外名片承载长期内容更新。网站内容需要易维护，优先通过 Markdown 文件管理，避免每次更新内容都改业务代码。

本项目同时用于验证 `harness-enterprise-template` 的企业级流程：项目创建后先进入 bootstrap 治理，再经过 PRD、技术方案、任务拆解、task queue、实现、测试、提交和 PR/MR。

## 2. 目标

- 建立一个简洁、美观、现代互联网产品风格的个人网站。
- 清晰展示个人介绍、技能方向、代表作品、联系方式。
- 支持通过 Markdown 维护作品、文章或项目案例内容。
- 支持基础 SEO 信息，让页面适合公开访问和分享。
- 支持后续扩展博客、项目案例详情、多语言或主题切换。
- 通过企业级 harness 流程验证从文档确认到 PR/MR 的完整闭环。

## 3. 目标用户

- 招聘方、合作方、客户或潜在业务伙伴。
- 想快速了解作者经历、能力、作品质量的人。
- 通过搜索、社交链接或 GitHub 进入网站的访问者。
- 作者本人，作为内容维护者。

## 4. 用户价值

- 访问者能在首屏快速理解“这是谁、擅长什么、有什么作品、如何联系”。
- 访问者能浏览代表作品，并进入更详细的项目案例。
- 作者能用 Markdown 更新内容，降低维护成本。
- 网站本身能体现作者对工程质量、设计审美和交付流程的重视。
- 页面内容应达到成熟个人网站的基本信息密度，不能停留在临时占位页或简单作品卡片层级。
- 首版展示语言以中文为主，英文仅保留在技术名词、项目名、外部品牌名或代码字段中。

## 5. 范围

### 5.1 In Scope

- 首页：个人名称、定位、简介、核心能力、联系方式。
- 作品集列表：作品标题、摘要、标签、时间、链接。
- 作品详情：从 Markdown 内容生成详情页或详情内容区。
- 内容维护：使用 Markdown 文件和 frontmatter 维护作品/文章。
- 响应式布局：桌面和移动端都可正常阅读。
- 基础 SEO：标题、描述、Open Graph 信息。
- 基础可访问性：语义化结构、键盘可访问、颜色对比合理。
- 中文化内容体验：首页、按钮、章节标题、作品摘要和联系方式以中文表达为主。
- 内容丰富化：首页应包含清晰定位、价值主张、工作方式、代表成果、精选作品、写作/观点入口和联系说明。
- 质量验证：lint、typecheck、test、coverage、smoke、e2e。

### 5.2 Out of Scope

- 后台 CMS。
- 用户登录。
- 在线评论。
- 复杂动画编辑器。
- 支付、预约或 CRM 集成。
- 服务端数据库。

## 6. 内容模型

### 6.1 个人信息

- 姓名或展示名。
- 一句话定位。
- 个人简介。
- 所在城市或远程协作说明。
- 联系方式。
- 社交链接，如 GitHub、LinkedIn、Email。

### 6.2 作品内容

作品建议通过 Markdown 文件维护，每个作品包含：

- `title`
- `summary`
- `date`
- `role`
- `tags`
- `cover` 可选
- `externalUrl` 可选
- `repoUrl` 可选
- 正文内容：背景、问题、方案、结果、反思。

### 6.3 文章内容 可选

后续可扩展文章或笔记：

- `title`
- `description`
- `date`
- `tags`
- Markdown 正文。

## 7. 产品结构

首版建议采用轻量结构：

```text
首页
├── Hero: 个人介绍和主要行动入口
├── About: 个人简介和能力方向
├── Works: 代表作品列表
├── Writing: 文章或思考，可首版隐藏或作为后续扩展
└── Contact: 联系方式和社交链接
```

作品详情可以在首版做成独立页面，也可以先做同页详情入口；具体在技术方案阶段确认。

## 8. 设计原则

- 内容优先：不为了视觉炫技牺牲可读性。
- 简洁现代：使用克制配色、清晰排版、足够留白。
- 有一点记忆点：可以通过字体层级、布局节奏、轻微交互体现个人风格。
- 工程可信：页面性能、可访问性、测试和交付流程本身也是作品的一部分。
- 易维护：内容更新应主要发生在 Markdown 文件中。

## 9. 验收标准

- 访问首页时，能看到个人介绍、核心能力、作品集和联系方式。
- 首页应具备足够内容密度，包括个人定位、工作方式、成果摘要、精选作品、写作/观点入口和联系说明。
- 页面可见文案应以中文为主，避免中英文混杂造成风格割裂。
- 至少有 3 个作品条目，可由 Markdown 内容生成。
- Markdown frontmatter 解析失败时，构建或测试应能暴露问题。
- 移动端和桌面端布局不破碎，文字不重叠。
- 关键页面有基础 SEO metadata。
- `lint`、`typecheck`、`test`、`coverage`、`smoke`、`e2e` 全部通过。
- task queue 只能在 PRD、技术方案、任务拆解确认后执行。
- 有 GitHub remote 和 SCM CLI 时，workflow 能推送任务分支并创建到 `develop` 的 PR。

## 10. 风险与约束

- 技术栈尚未确认，需在技术方案阶段讨论。
- GitHub 仓库地址已确定为 `git@github.com:slightlee/personal-site.git`，但本地是否已具备 SSH 权限和 PR CLI 能力需要在实现前验证。
- 内容维护使用 Markdown，但具体选 Markdown、MDX 或静态内容解析库，需要在技术方案阶段确认。
- 视觉风格需要避免过度动效和过重装饰，优先保证可读性、性能和维护性。

## 11. 市场与范式观察

- 现代个人网站通常采用清晰导航：Home、About、Work/Portfolio、Blog 可选、Contact。
- 个人作品集趋势更强调内容质量、案例叙事、过程说明和结果，而不是只有卡片列表。
- Markdown/MDX 适合个人网站内容维护，既能保持文件化内容，也能支持扩展组件。
- 视觉上建议采用留白、强排版、低噪声配色和少量微交互，形成“简洁但不单薄”的产品感。
- 2026-05-16 补充调研：成熟个人站通常通过强首屏叙事、精选文章/作品、可信数字、清晰导航和统一语言系统建立信任感；本项目首版应补齐这些信息层级。
